# 拖拽检查

拖动中的图像位置只是预览。松手后，视图先把屏幕位置换成棋盘格，处理最近合成高亮的短暂吸附和教程指定落点，再检查拖入棋子能否移动。指针落在仓库上时先尝试存入；存入失败才回到棋盘处理。

进入棋盘模型后，依次检查目标坐标是否合法、源格是否仍是这只棋子。任一步不通过就复位并结束，不再尝试特殊作用、合成或交换。这样可以防止拖动期间对象已经消失或被替换，却仍用过期图像修改棋盘。

## 判断与分支（按触发位置）

1. **拖动资格**：先检查拖入棋子能否移动。纸箱、蜘蛛网、锁定物不能作为拖动源；吞噬物还取决于它是否允许点击。首次有效拖动通知教程和界面，之后图像跟随手指，棋盘模型尚未换格。
2. **落点吸附与教程限制**：松手位置先转为格坐标。刚显示过的合成高亮可以在短时间内把落点吸到对应棋子；教程指定目标不满足时改成非法坐标。它们改变传给模型的落点，不改变普通合成的代码匹配规则。
3. **棋子入库**：指针落在仓库按钮上时，先检查仓库是否开启、物品是否能存、仓库是否有容量。成功则从棋盘移入仓库，本次不进行棋盘合成；失败会提示原因，再按实际棋盘落点继续分派。
4. **坐标与对象校验**：先排除棋盘外落点，再核对源格对象。如果拖动期间源格被替换，旧棋子的拖动也会被拒绝。这两项先于读取目标棋子，防止过期输入继续执行。

## 演示案例

下面分别改变前提，让各条分支实际发生；互斥结果属于不同场景。

### 场景1：可以拖动的普通食物

**本例情境：** 玩家开始拖动一件未锁定的普通201。

**判断与目的：** 逐项检查限制，没有限制便让图像跟随手指。

**玩家看到的结果：** 201跟随手指，源格的实际棋子尚未移动；没有扣能量。

### 场景2：短时间高亮吸附

**本例情境：** 玩家松手时，本例的高亮吸附或教程限制正在参与落点判断。

**判断与目的：** 高亮仍在吸附有效时间内，松手格也足够近，改用高亮格。

**玩家看到的结果：** 本来松手在原格的201被送到右上方高亮棋子所在格，后续按该格判断合成。

### 场景3：教程指定落点

**本例情境：** 玩家松手时，本例的高亮吸附或教程限制正在参与落点判断。

**判断与目的：** 松手格与教程要求不一致，送入无效落点以便复位。

**玩家看到的结果：** 201回到原格，目标不改变，没有合成或扣能量。

### 场景4：成功存入仓库

**本例情境：** 玩家把201拖到已开启且有空容量的仓库按钮。

**判断与目的：** 先核可存资格，再核容量；成功存入便结束棋盘分派。

**玩家看到的结果：** 棋盘少一件201，仓库从2件变3件；仍持有这件物品，本次不合成。

### 场景5：拒绝过期拖动对象

**本例情境：** 拖动期间原201被同类型新对象替换，玩家仍在释放旧对象。

**判断与目的：** 格子内的物品身份与拖动对象不同，拒绝继续。

**玩家看到的结果：** 旧拖动被撤回，棋盘上的新201和目标棋子都保留，不消耗物品。
