# 棋子入库

指针落在仓库按钮上时，先检查仓库是否开启、物品是否能存、仓库是否有容量。成功则从棋盘移入仓库，本次不进行棋盘合成；失败会提示原因，再按实际棋盘落点继续分派。

## 本机制怎样执行

是否落在仓库 → 功能开启 → 物品可存 → 容量足够 → 存入；任一步失败回到棋盘落点。

本页说明这一步的条件与结果；下一层给出对应变量、比较、完整配表与数值推演。

## 演示案例

本例设定本机制所需条件，演示它实际触发后的结果。

### 场景1：成功存入仓库

**本例情境：** 玩家把201拖到已开启且有空容量的仓库按钮。

**判断与目的：** 先核可存资格，再核容量；成功存入便结束棋盘分派。

**玩家看到的结果：** 棋盘少一件201，仓库从2件变3件；仍持有这件物品，本次不合成。
