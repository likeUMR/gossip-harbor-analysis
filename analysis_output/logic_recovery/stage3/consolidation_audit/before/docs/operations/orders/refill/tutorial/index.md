# 教程订单

固定与回归没有建单时才检查教程。它按当前教程进度读预设需求，不走普通随机；已经不需要的教程会被跳过，资格查询可能推进进度。

## 内部处理顺序与目的

1. 读取当前教程进度和预设配置，检查槽位与是否待创建。

2. 已解锁跳过物就推进并递归，否则要求目标母体解锁。

3. 保存进行中状态再建单；完成通知之后推进下一教程。

---

## 演示案例

本例设定本机制所需条件，演示它实际触发后的结果。

### 场景1：预设教程需求触发

**本例情境：** 当前教程待创建，要求母体已解锁、教程尚不能跳过，预设需求为203。

**判断与目的：** 教程仍需要做且母体已解锁，先写进行中再创建。

**玩家看到的结果：** 槽1出现要求203的教程订单；交付完成后进入下一教程待创建状态，不使用普通随机点数。
