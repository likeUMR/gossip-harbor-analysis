# 扣物刷新与缺物处理

每件尝试之后刷新真实数量和其它订单状态。某项没找到也继续处理后面的需求；先发奖再扣物的顺序必须保留，不能用“交付成功”概括所有异常。

## 内部处理顺序与目的

1. 每件尝试后重新计数并刷新订单状态。

2. 材料不足只记错误，前面已发奖励和已扣材料不会回滚，仍继续后续结算。

---

## 演示案例

本例设定本机制所需条件，演示它实际触发后的结果。

### 场景1：确认后第三件丢失

**本例情境：** 玩家确认后仓库204消失，但结算仍已发8金币。

**判断与目的：** 每项刷新一次，缺物记录错误但继续，不撤回已发奖励。

**玩家看到的结果：** 两件203消耗、订单仍完成、金币仍108；204缺失被记录，没有自动补物或退回奖励。
