# 订单类型判断

特殊与分支在普通奖励之前接管。订单对象的内部类型与用于显示/日志的Fixed、Random、Special大类不同，判断必须使用内部类型。

## 内部处理顺序与目的

1. 读取内部类型，先判断特殊任务，再判断分支任务。

2. 任一专用路径处理后立即返回，其余才进入普通结算。

---

## 演示案例

本例设定本机制所需条件，演示它实际触发后的结果。

### 场景1：分流决定执行链

**本例情境：** 分别把本次订单设为普通订单、特殊任务或分支任务。

**判断与目的：** 先识别特殊任务，再识别分支任务；其余才进入普通结算。

**玩家看到的结果：** 普通单领8金币并扣三件需求；特殊与分支单各走专用清链和奖励，不再叠加普通单8金币。
