# 需求数量核对

逐项核对，同一种物品出现两次就需要两件。失败返回每种代码的缺口，窗口据此展示需要动用哪些仓库物。空需求会通过本方法，不能只依靠方法名假设它必定拒绝。

## 内部处理顺序与目的

1. 保留需求顺序，把重复代码累计为需要的件数。

2. 逐项比较持有数量，汇总缺口；不在第一次失败时停止。

3. 返回是否足够与缺口，让入口选择直接提交或确认窗。

---

## 演示案例

本例设定本机制所需条件，演示它实际触发后的结果。

### 场景1：重复需求缺口

**本例情境：** 棋盘只有一件203，订单却需要两件203和一件204。

**判断与目的：** 每个重复需求都累加需要数量，逐项查出全部缺口。

**玩家看到的结果：** 窗口要求从仓库补一件203和一件204，不能用一件203满足两个需求；此时未扣物。
