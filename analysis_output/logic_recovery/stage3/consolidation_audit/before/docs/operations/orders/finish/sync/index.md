# 状态刷新与同步

全局OrderFinished先于棋盘局部FinishOrder；同步上传检查夹在局部消息之前。首轮微笑提示只在先前资格满足时派发。

## 内部处理顺序与目的

1. 所属模型补位与全局通知返回后，再刷新主棋盘状态。

2. 满足首轮微笑资格才提示，随后检查同步上传。

3. 最后派局部完成消息，把奖励和扣物快照交给视图。

---

## 演示案例

本例设定本机制所需条件，演示它实际触发后的结果。

### 场景1：首轮提示与完成消息

**本例情境：** 三件材料已扣、8金币已发，本单符合首次微笑提示条件。

**判断与目的：** 先处理所属模型全局完成通知，再刷新、发首轮提示、检查同步，最后交视图。

**玩家看到的结果：** 金币108、三件物品已扣；玩家看到首轮微笑提示，随后进入交付表现，同步检查不会再发8金币。
