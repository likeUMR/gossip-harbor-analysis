# 新订单创建的优先级

每个槽先试固定、回归免费、教程、连续活动、额外顾客、Lucky，最后才普通随机。前者成功就跳过后者。选择头像和保存礼物也发生在创建链里，不能理解为只随机几个需求。

## 内部处理顺序与目的

1. 按固定、回归、教程、连续活动、额外顾客、Lucky、普通随机依次尝试。

2. 第一个成功对象结束选择，补头像、礼物和必要编号。

3. 派新单创建消息后返回，随后外层才把对象保存进槽位。

---

## 演示案例

本例设定本机制所需条件，演示它实际触发后的结果。

### 场景1：固定单先于随机单

**本例情境：** 槽1符合下一条固定订单资格，其它随机建单不能抢先。

**判断与目的：** 按优先级固定单第一个成功，停止后续创建器。

**玩家看到的结果：** 槽1出现固定需求203的新顾客；不消耗普通随机创建次数，也没有额外Lucky需求。
