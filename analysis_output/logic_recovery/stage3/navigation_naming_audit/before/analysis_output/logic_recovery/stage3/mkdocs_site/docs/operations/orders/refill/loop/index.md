# 完成日志与多轮补位

槽位模型先完成旧单并记日志，再扫描全部槽位。某个空槽本轮没补上，若其它槽成功创建，下一轮会再次尝试；一轮完全没有新订单才停止。全局完成通知在补位之后。

## 内部处理顺序与目的

1. 记录旧订单完成，然后扫描全部空槽和已完成槽。

2. 移除旧单，尝试创建新单；成功才保存并放入槽位。

3. 只要本轮有一个成功就再扫一轮；最终刷新并派完成通知。

---

## 演示案例

本例设定本机制所需条件，演示它实际触发后的结果。

### 场景1：补位成功再扫描一轮

**本例情境：** 槽1旧单已完成，槽2为空；本轮只有槽2能成功建单。

**判断与目的：** 扫描空槽，保存成功新单；本轮有成功就再扫描一次。

**玩家看到的结果：** 槽2出现需求503的新顾客，槽1暂时空着；本次没有无限尝试，也没有重复保存槽2订单。
