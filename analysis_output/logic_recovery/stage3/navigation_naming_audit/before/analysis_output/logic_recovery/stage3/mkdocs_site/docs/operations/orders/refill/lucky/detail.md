# Lucky订单：资格、现有库存与有限连续次数：具体算法与配置

CanCreate仅槽17且CanTriggerLucky；通过入口即CloseTriggerLucky，之后配置缺失或等级失败也已消耗本次资格。points>1允许；points==1写timer=now、points0并拒绝；points0则lastTime+RefreshTime≤now才允许。Create按Lucky配置第一个匹配Filter和三个等级区间生成候选；TryLuckyRandom取board+store计数，剔除其它订单已有需求code（测试模式可跳本槽），Weight>0且count映射非nil才候选并存CurNum。首候选空时失败，原points非0则清点并启动CD。

ItemAmounts缺字段补0，三键全缺则回退等级档，按非空第一/第二/第三池构Count1/2/3权重后先选需求数。抽第一code后在第二与第三池同code的CurNum−1，到0移除；第二同样影响第三。这是按当前可用库存份额防超额，原Weight不按数量成比例扣减；同code有2件时可以出现2次。后池为空则少于抽中的目标项数也能建单。成功points非0→points−1，否则→配置Point；不是先设Point再减1。下次候选按实时库存重建，交付才实际扣物。

GetSelectedFilter依PlayerMin/Max、DiffSumMin/Max、sMonthPay/eMonthPay含端点且按数组第一条匹配；无匹配后续解引用失败没有通用默认。配置变体的IsLucky行才被LoadFileConfig单独保存；默认OrderRandom未出现不意味着机制无代码。

## 对应本地配表

各后缀为可选变体，不是同时叠加。require受FileReplace精确文件名首匹配替换，失败才回退默认；实际账号选择及远端档位未取得。缺字段记“—”，不能当0。下方保留全记录与全部字段；嵌套Filters/Rewards可横向滚动查看。

**OrderRandomConfig字段含义：** Type索引内部类型，IsLucky=1行独立选为Lucky配置；UnlockLevel等级门槛，RefreshTime秒，Point批次可创建次数，LuckyTriggerChance为浮点阈值（缺省不抽）；Filters按数组首匹配，Player/DiffSum/MonthPay上下界含端点，First/Second/Third及Dynamic上限控制逐项难度；ItemAmounts是一/二/三项权重，不是产物code权重。
