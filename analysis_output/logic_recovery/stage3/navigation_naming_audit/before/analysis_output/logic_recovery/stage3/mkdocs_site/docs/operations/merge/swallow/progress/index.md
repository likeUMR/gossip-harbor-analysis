# 吞入、保存与进度通知

匹配后先更新目标进度并保存，再删除拖入物、通知吞噬与刷新进度。最后检查全部需求是否完成；未完成则保留目标等待下一件。

## 本机制怎样执行

增加匹配项 → 保存目标进度 → 删除输入并通知 → 核对所有需求 → 未完成等待下一件。

本页说明这一步的条件与结果；下一层给出对应变量、比较、完整配表与数值推演。

## 演示案例

本例设定本机制所需条件，演示它实际触发后的结果。

### 场景1：吞入第一件但尚未完成

**本例情境：** 目标需要两件201，尚未吞入任何一件，玩家拖入第一件。

**判断与目的：** 接受尚缺的一件，保存进度并删拖入物，再检查是否完成。

**玩家看到的结果：** 201消失，目标从0/2变1/2，还需一件201；本次没有奖励变换，也不交换。
