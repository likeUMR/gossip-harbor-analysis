# 创建需求、固定池与拖入资格

目标创建时为最多两项需求选代码和数量。玩家拖入时按完整物品代码检查需求是否尚缺；目标是否允许点击影响移动资格，但不是拖入吞噬的额外门槛。

## 本机制怎样执行

目标创建时选定需求并保存 → 拖入时比对完整代码与剩余数量 → 匹配才接收。

本页说明这一步的条件与结果；下一层给出对应变量、比较、完整配表与数值推演。

## 演示案例

本例设定本机制所需条件，演示它实际触发后的结果。

### 场景1：有限池确定吞噬需求

**本例情境：** 创建一个需要吞入食物的目标，并把201拖向它。

**判断与目的：** 创建目标时打乱有限份额并消费一份；拖入时只比需求，不重新抽奖。

**玩家看到的结果：** 这个目标需要吞入两件201；拖入201会被接受。下一目标继续使用剩余份额，本次拖入没有重抽需求。
