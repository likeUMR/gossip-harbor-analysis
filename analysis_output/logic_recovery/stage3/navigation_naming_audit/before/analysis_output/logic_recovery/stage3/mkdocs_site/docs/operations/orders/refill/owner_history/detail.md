# 所属校验与下一单使用的状态：具体算法与配置

MainBoardModel遍历m_orderModels以pairs ContainsOrder，首个命中FinishOrder并break；没有命中也继续尾部Update/Sync/局部消息，不撤即时奖励。MainOrderModel.FinishOrder在父类ContainsOrder校验前就执行副作用：Branch标finished；CharacterIntimacy.OnMainOrderFinished；m_canTriggerLucky=false，IsLuckyOrder真设true，否则GetRandomOrderConfigBySlot(slot)[innerType]有LuckyTriggerChance才MathUtil.Random()≤chance设true。无参Random正常返回math.random()浮点，测试可缩窄区间，不保存机会池；没有参数时nil分支不抽。NormalOrderSlot真则TotalDiffScore+=GetDiffScore；每个需求配置RepeatWeightDecrease>0将所属链计数reset为3并保存。重复code可多次reset并保存。最终SlotOrderModel.FinishOrder再次ContainsOrder失败返false，但主订单前述副作用已发生。

## 对应本地配表

各后缀为可选变体，不是同时叠加。require受FileReplace精确文件名首匹配替换，失败才回退默认；实际账号选择及远端档位未取得。缺字段记“—”，不能当0。下方保留全记录与全部字段；嵌套Filters/Rewards可横向滚动查看。

**OrderRandomConfig字段含义：** Type索引内部类型，IsLucky=1行独立选为Lucky配置；UnlockLevel等级门槛，RefreshTime秒，Point批次可创建次数，LuckyTriggerChance为浮点阈值（缺省不抽）；Filters按数组首匹配，Player/DiffSum/MonthPay上下界含端点，First/Second/Third及Dynamic上限控制逐项难度；ItemAmounts是一/二/三项权重，不是产物code权重。

### 场景1：普通单取得下一次Lucky资格

**完整输入（演示设定）：** 普通槽1订单需求按序203、203、204；棋盘(1,1)/(2,1)各裸203，仓库索引1裸204，缓存空；等级10，Gold100、Energy10、TotalDiff100。203价格2/难度2，204价格4/难度5。假设所属模型ContainsOrder=true，该类型LuckyTriggerChance=0.25，无重复链衰减字段。

**按执行顺序代入：** u=0.2≤0.25→m_canTriggerLucky=true；TotalDiff100+9=109；低阶需求无RepeatWeightDecrease，不reset。

**玩家看到的结果：** 累计难度变109，本次拿到下一次Lucky订单尝试资格；不等于下一单必定创建成功，还要满足槽位和冷却。
