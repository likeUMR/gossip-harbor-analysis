# 缓存奖励与完成状态

完成状态写在扣除之前。完成后的奖励读取走缓存，但缓存首次填充可能重新调用奖励计算，不能认为即时快照就是唯一一次计算。

## 内部处理顺序与目的

1. 冻结完成时的奖励供后来显示。

2. 直接把订单标为完成，让后续刷新不再把它改回可交付状态。

---

## 演示案例

本例设定本机制所需条件，演示它实际触发后的结果。

### 场景1：完成后固定奖励读取

**本例情境：** 8金币已发，订单尚未开始扣物，准备写完成状态。

**判断与目的：** 缓存奖励并标完成，让后面的数量刷新不再把旧单改回可交付。

**玩家看到的结果：** 订单显示完成，之后读到的仍是本次8金币奖励；此步不再发8金币，余额保持108。
