# 仓库确认与关闭后的提交

窗口重新算棋盘缺口并展示，确认只设置提交标记；真正提交在窗口关闭完成后。普通入口只检查订单还在不在槽位，没有再次核对库存，也不会先把仓库物移到棋盘。

## 内部处理顺序与目的

1. 窗口重算棋盘缺口，展示需要用仓库补交的物品。

2. 取消只关闭；确认先记录意愿，再等窗口关闭完成。

3. 关闭回调优先执行专用回调，否则确认订单仍在槽位才提交；这里没有再次检查材料数量。

### 场景1：确认仓库补交

**本例情境：** 玩家确认使用仓库的204补交，关闭期间订单和材料均未变化。

**判断与目的：** 记录确认意愿，关闭动画结束后核订单仍在，再提交。

**玩家看到的结果：** 确认后获得8金币，三件需求都被消耗，订单完成；能量仍10。
