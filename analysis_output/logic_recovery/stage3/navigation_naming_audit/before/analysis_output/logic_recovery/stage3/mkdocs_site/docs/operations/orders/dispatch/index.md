# 进入模型：先分流特殊与分支订单

进入FinishOrder后先按订单内部类型分流。特殊任务清理相关整条链并发配置奖励；分支任务清理链并把有限奖励池全部发完。这两条路径立即返回，普通订单才继续后面的价格、奖励、逐件扣除和补位顺序。

## 本阶段的判断与处理顺序

1. **内部类型决定执行路径**：特殊与分支在普通奖励之前接管。订单对象的内部类型与用于显示/日志的Fixed、Random、Special大类不同，判断必须使用内部类型。

2. **特殊任务：完成模型、清整链、发奖**：先完成所属订单模型，再取当前特殊配置清理需求链和母体链。清理覆盖棋盘、仓库、缓存；气泡按内含物判断。然后发配置奖励、标记时间线并通知特殊完成。

3. **分支任务：抽一份减一份直到耗尽**：分支奖励的权重表示必须发出的份数，同时影响下一件出现概率。每次抽取减1，全部份数耗尽才结束；棋盘没有空位就进缓存。因此随机改变发放顺序，不改变最终配置总件数。

---

## 演示案例

下面分别改变前提，让各条分支实际发生；互斥结果属于不同场景。

### 场景1：分流决定执行链

**本例情境：** 分别把本次订单设为普通订单、特殊任务或分支任务。

**判断与目的：** 先识别特殊任务，再识别分支任务；其余才进入普通结算。

**玩家看到的结果：** 普通单领8金币并扣三件需求；特殊与分支单各走专用清链和奖励，不再叠加普通单8金币。

### 场景2：特殊任务完成清链

**本例情境：** 玩家交付任务1，任务要求清理的物品分布在棋盘、仓库和缓存。

**判断与目的：** 完成任务后清理需求链和母体链，再发专用奖励、写任务完成标记。

**玩家看到的结果：** 两条任务相关链从棋盘、仓库和缓存清除；宝石变35、能量变110，任务1完成。

### 场景3：分支奖励有限池全部发完

**本例情境：** 玩家完成槽7的分支任务，六件奖励要发完，但棋盘只有两个空格。

**判断与目的：** 按剩余份额随机一件就减一份，直到所有奖励发完；空间不足的进入缓存。

**玩家看到的结果：** 棋盘收到2402和2405各一件；缓存收到2402一件、2502两件、2503一件；顺序随机，总共六件不会少发。
