# 棋盘未找到才扣仓库

同一需求只要棋盘已扣到，就不再扣仓库。棋盘找不到时扫描仓库索引，删除第一件匹配物并删除保存属性；缓存不在兜底范围。

## 内部处理顺序与目的

1. 仅当棋盘没找到这件需求时，从仓库第一项顺序查找。

2. 删除第一个精确匹配项和它的保存属性，保留原需求索引；缓存不参与。

### 场景1：缺物才动仓库

**本例情境：** 两件203已从棋盘扣到，最后一件204只在仓库。

**判断与目的：** 只为尚未扣到的需求扫描仓库，删除首个匹配项。

**玩家看到的结果：** 仓库的204被消耗，前两项不会再额外扣仓库203；三件需求合计只扣三件。
