# 扣物之后：烹饪奖励、宝箱通知与延迟发奖

扣除完成后才尝试烹饪狂热奖励，因此刚腾出的格可能成为奖励落点。之后通知宝箱顾客完成，再发之前分离出的延迟奖励，最后才进入所属订单模型的完成与补位。

## 本阶段的判断与处理顺序

1. **烹饪狂热：选奖、选物与落点**：先按订单难度匹配当前Buff。单奖模式先决定奖励类别，再在棋子奖内部优先帮助订单缺口；全奖模式遍历全部奖励。可放棋盘的直接生成，其余交奖励API；它有自己的候选与去重，不能套普通母体随机池。

2. **宝箱顾客通知，再发延迟奖励**：先派宝箱顾客完成通知，然后发快照中各组延迟奖励。通知本身与奖励标记落账不同；两者都发生在槽位补位之前。

---

## 演示案例

下面分别改变前提，让各条分支实际发生；互斥结果属于不同场景。

### 场景1：烹饪奖励优先帮助微笑缺口

**本例情境：** 烹饪Buff有效且命中订单难度档，扣物后有可用空格；分别演示抽奖与全奖。

**判断与目的：** 先为棋子槽挑帮助对象，再抽奖类别；命中棋子类别后按缺口优先级选内部奖。

**玩家看到的结果：** 扣物后额外在棋盘生成一件203，优先帮助剩余微笑订单；本次没有领取那份2金币候选奖励。

### 场景2：全奖模式含棋子与货币

**本例情境：** 烹饪Buff有效且命中订单难度档，扣物后有可用空格；分别演示抽奖与全奖。

**判断与目的：** 全奖模式不抽类别，逐份生成固定棋子并发货币。

**玩家看到的结果：** 棋盘多两件204，金币余额111；全奖模式同时得到配置中的两种奖励。

### 场景3：预算允许最后一件超支

**本例情境：** 宝箱活动有效，旧订单仍可取到；预算五份、每件203成本三份，棋盘一个空格。

**判断与目的：** 通知宝箱完成，再把标记换成预算，重复抽物直到预算耗尽，不能把标记当一件奖励。

**玩家看到的结果：** 共获得两件203，一件在棋盘、一件在缓存；预算虽是5，最后一件允许跨过预算边界。

### 场景4：缺口整单容差补齐

**本例情境：** 宝箱活动有效，旧订单仍可取到；预算五份、每件203成本三份，棋盘一个空格。

**判断与目的：** 预算接近整张订单所缺难度时，允许小幅超预算，直接给齐缺口。

**玩家看到的结果：** 棋盘多一件203和一件204，把这张订单的缺口全部补齐；预算允许超出两份。

### 场景5：高难度缺口用旧降阶算法

**本例情境：** 宝箱活动有效，旧订单仍可取到；预算五份、每件203成本三份，棋盘一个空格。

**判断与目的：** 整件目标远超预算，沿同链降到较便宜等级，按预算向上取整发帮助物。

**玩家看到的结果：** 棋盘获得两件206，帮助继续合成209；没有直接发出209，末件仍允许超预算。

### 场景6：库存优化停止定向后用余款补奖

**本例情境：** 宝箱活动有效，旧订单仍可取到；预算五份、每件203成本三份，棋盘一个空格。

**判断与目的：** 考虑现有低阶合成库存，只补尚缺的等价份额，再把余款转为普通五级奖励。

**玩家看到的结果：** 棋盘额外获得一件206和两件205；定向补缺没有继续重复发206，剩余预算仍作为普通奖励用完。
