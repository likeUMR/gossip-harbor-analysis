# 烹饪狂热：选奖、选物与落点

先按订单难度匹配当前Buff。单奖模式先决定奖励类别，再在棋子奖内部优先帮助订单缺口；全奖模式遍历全部奖励。可放棋盘的直接生成，其余交奖励API；它有自己的候选与去重，不能套普通母体随机池。

## 内部处理顺序与目的

1. 用订单难度匹配当前烹饪Buff档位，决定全奖还是抽奖。

2. 棋子候选优先考虑微笑缺口、普通缺口，再考虑其它可用物。

3. 按可用空格决定落盘或资源逻辑，保留结果给后续动画。

---

## 演示案例

下面分别改变前提，让各条分支实际发生；互斥结果属于不同场景。

### 场景1：烹饪奖励优先帮助微笑缺口

**本例情境：** 烹饪Buff有效且命中订单难度档，扣物后有可用空格；分别演示抽奖与全奖。

**判断与目的：** 先为棋子槽挑帮助对象，再抽奖类别；命中棋子类别后按缺口优先级选内部奖。

**玩家看到的结果：** 扣物后额外在棋盘生成一件203，优先帮助剩余微笑订单；本次没有领取那份2金币候选奖励。

### 场景2：全奖模式含棋子与货币

**本例情境：** 烹饪Buff有效且命中订单难度档，扣物后有可用空格；分别演示抽奖与全奖。

**判断与目的：** 全奖模式不抽类别，逐份生成固定棋子并发货币。

**玩家看到的结果：** 棋盘多两件204，金币余额111；全奖模式同时得到配置中的两种奖励。
