# 重复需求按件数检查

逐项核对，同一种物品出现两次就需要两件。失败返回每种代码的缺口，窗口据此展示需要动用哪些仓库物。空需求会通过本方法，不能只依靠方法名假设它必定拒绝。

## 内部处理顺序与目的

1. 保留需求顺序，把重复代码累计为需要的件数。

2. 逐项比较持有数量，汇总缺口；不在第一次失败时停止。

3. 返回是否足够与缺口，让入口选择直接提交或确认窗。

---

## 贯穿案例：203×2与204×1，使用仓库补交

两个203逐项通过，204缺1件；不是把重复203去重后判断。
