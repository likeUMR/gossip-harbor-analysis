# 扣物之后：烹饪奖励、宝箱通知与延迟发奖

扣除完成后才尝试烹饪狂热奖励，因此刚腾出的格可能成为奖励落点。之后通知宝箱顾客完成，再发之前分离出的延迟奖励，最后才进入所属订单模型的完成与补位。

## 本阶段的判断与处理顺序

1. **烹饪狂热：选奖、选物与落点**：先按订单难度匹配当前Buff。单奖模式先决定奖励类别，再在棋子奖内部优先帮助订单缺口；全奖模式遍历全部奖励。可放棋盘的直接生成，其余交奖励API；它有自己的候选与去重，不能套普通母体随机池。

2. **宝箱顾客通知，再发延迟奖励**：先派宝箱顾客完成通知，然后发快照中各组延迟奖励。通知本身与奖励标记落账不同；两者都发生在槽位补位之前。
