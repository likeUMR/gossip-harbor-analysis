# 标记完成，再逐项扣需求物品

先缓存奖励并标完成，再按原需求顺序一件一件扣物。每项先找棋盘，再找仓库；每次都重新统计并刷新订单。两处没有就记错误并继续，源码没有撤销已经发放的奖励。

## 本阶段的判断与处理顺序

1. **缓存奖励与完成状态**：完成状态写在扣除之前。完成后的奖励读取走缓存，但缓存首次填充可能重新调用奖励计算，不能认为即时快照就是唯一一次计算。

2. **按棋盘遍历序扣第一件匹配物**：逐项找裸代码相同的第一件棋盘物，不按最近距离或等级挑选。同code重复需求会在后一次扫描找到另一实例。

3. **棋盘未找到才扣仓库**：同一需求只要棋盘已扣到，就不再扣仓库。棋盘找不到时扫描仓库索引，删除第一件匹配物并删除保存属性；缓存不在兜底范围。

4. **逐件刷新与部分失败边界**：每件尝试之后刷新真实数量和其它订单状态。某项没找到也继续处理后面的需求；先发奖再扣物的顺序必须保留，不能用“交付成功”概括所有异常。
