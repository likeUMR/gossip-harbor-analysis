# 缓存奖励与完成状态

完成状态写在扣除之前。完成后的奖励读取走缓存，但缓存首次填充可能重新调用奖励计算，不能认为即时快照就是唯一一次计算。

## 内部处理顺序与目的

1. 冻结完成时的奖励供后来显示。

2. 直接把订单标为完成，让后续刷新不再把它改回可交付状态。

---

## 贯穿案例：203×2与204×1，使用仓库补交

无活动状态变化，奖励缓存仍为Gold8，状态改4，再开始扣物。
