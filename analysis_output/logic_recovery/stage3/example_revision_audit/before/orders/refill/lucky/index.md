# Lucky订单：资格、现有库存与有限连续次数

完成订单只提供一次触发资格，Lucky创建还要检查等级、次数与冷却。需求只从现有且不被其它订单占用的代码中选，重复需求不能超出现有件数；连续次数保存在元数据，不能把它当母体Lucky机会池。

## 内部处理顺序与目的

1. 先消耗本次触发资格，再检查配置、等级、连续次数与冷却。

2. 从未被其它单占用的现有库存建立三个候选池，先决定需求数。

3. 逐项抽代码并扣后续池的可用份数，成功或失败分别更新次数与冷却。

## 贯穿案例：203×2与204×1，使用仓库补交

本例默认Random1没有触发机会且Lucky资格关闭，不创建Lucky。对照已有两件203时，需求可选两次203，第三次会被CurNum约束。
