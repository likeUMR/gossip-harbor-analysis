# 重建候选：解锁、现有需求与权重修正

每个需求位置重新构建候选，排除尚不可用物和已被需求占用的代码，按库存情况修正权重。第一项可在特定活动条件下使用备用候选；不是每次都从完整物品表直接抽。

## 内部处理顺序与目的

1. 读取扣物后的库存与现有需求，先计算链和代码权重倍率。

2. 逐代码累积检查等级、解锁、槽位、上次单与其它单排除条件。

3. 分出主候选与特定条件下可用的备用池，保留实际遍历顺序。
