# 所属模型完成：更新历史，再补订单

普通交付寻找仍包含该订单的模型。主订单先更新亲密度、下一次Lucky资格、累计难度与重复链权重；槽位模型再写完成、日志，移除旧槽并按优先级补新订单。补位是多轮且含固定、教程、活动和随机分支，最后才派全局订单完成通知。

## 本阶段的判断与处理顺序

1. **所属校验与下一单使用的状态**：寻找包含该对象的模型之后，更新影响下一单的状态。Lucky订单保持下一次触发资格，普通订单仅在配置提供机会时抽一次；该Lucky与母体产出Lucky是两个系统。

2. **完成日志与多轮补位**：槽位模型先完成旧单并记日志，再扫描全部槽位。某个空槽本轮没补上，若其它槽成功创建，下一轮会再次尝试；一轮完全没有新订单才停止。全局完成通知在补位之后。

3. **新订单创建的优先级**：每个槽先试固定、回归免费、教程、连续活动、额外顾客、Lucky，最后才普通随机。前者成功就跳过后者。选择头像和保存礼物也发生在创建链里，不能理解为只随机几个需求。

4. **固定与回归免费订单**：固定单按进度的下一Id和槽/等级门槛创建，不随机需求。回归免费单在指定槽与回归时间内取现有较高等级物；计时资格与选物是两个步骤，构造失败也可能已经改计时。

5. **教程单：检查解锁、跳过旧教程、进入进行中**：固定与回归没有建单时才检查教程。它按当前教程进度读预设需求，不走普通随机；已经不需要的教程会被跳过，资格查询可能推进进度。

6. **连续订单：按本轮档位逐项抽需求**：教程未建单才尝试槽18连续订单。活动状态、进度和界面门控都通过后，按本轮三个需求范围逐项抽物；需求项数来自配置，不另抽普通订单的一二三项权重。

7. **额外顾客：创建空需求入口并保存活动标记**：连续订单未成功才检查槽19额外顾客。它先创建活动入口单，需求为空；不能套用普通随机需求或把空需求解释为已经可以完整领取活动奖励。

8. **Lucky订单：资格、现有库存与有限连续次数**：完成订单只提供一次触发资格，Lucky创建还要检查等级、次数与冷却。需求只从现有且不被其它订单占用的代码中选，重复需求不能超出现有件数；连续次数保存在元数据，不能把它当母体Lucky机会池。

9. **普通随机：槽位、次数与冷却**：随机创建首先选适用于槽位的创建器，再检查等级、批次次数和冷却。次数不足有活动强制补单例外；次数在资格通过时就扣，不能等创建成功后才扣。回归与宝箱顾客可选择不同配置。

10. **重建候选：解锁、现有需求与权重修正**：每个需求位置重新构建候选，排除尚不可用物和已被需求占用的代码，按库存情况修正权重。第一项可在特定活动条件下使用备用候选；不是每次都从完整物品表直接抽。

11. **选过滤档，再调整难度上限**：先按等级、累计难度和付费区间选第一条过滤档。常规等级上限可因库存有富余高阶物而提高，但只作用于符合条件的链；动态候选会被乘50增加机会。

12. **先选三个候选，再抽需求项数**：普通随机先顺序选第一、第二、第三候选，之后才按权重决定保留几项。因此最终只有一项的单，也可能已经消耗了第二、第三候选选择的随机数与权重状态。

13. **移除旧单、保存新单与重载**：旧单删除时保存上一单需求，供下一次过滤；新单保存需求、类型、头像和独立的Lucky/基准/难度标记。重载从这些值重新构造对象，不应重新随机一份需求。
