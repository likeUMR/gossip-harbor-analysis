# 不能合成：再尝试目标吞噬

只有普通合成失败才读取目标吞噬组件。目标需要这种物品且数量未满时，接收一件，保存进度并删除拖入物；所有需求都完成时变换成奖励物。吞噬成功立即结束，不再交换。

吞噬所需物品通常在目标创建时已经确定，拖入时只比对代码和剩余数量，不在每次拖动时重新随机需求。

## 判断与分支（按触发位置）

1. **创建需求、固定池与拖入资格**：目标创建时为最多两项需求选代码和数量。玩家拖入时按完整物品代码检查需求是否尚缺；目标是否允许点击影响移动资格，但不是拖入吞噬的额外门槛。
2. **吞入、保存与进度通知**：匹配后先更新目标进度并保存，再删除拖入物、通知吞噬与刷新进度。最后检查全部需求是否完成；未完成则保留目标等待下一件。
3. **需求完成后的奖励变换**：全部需求完成后，目标按变换权重选一个结果并原格替换。吞噬引起的变换不再额外消耗点击能量；不允许点击的吞噬物还会震动邻格，随后发全局吞噬完成通知。

主例已经合成并返回，吞噬不执行。吞噬对照改为一个要求201的目标，201被消耗、目标进度加1；这是另一条互斥路径。
