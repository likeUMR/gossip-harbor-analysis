# 吞噬完成变换

全部需求完成后，目标按变换权重选一个结果并原格替换。吞噬引起的变换不再额外消耗点击能量；不允许点击的吞噬物还会震动邻格，随后发全局吞噬完成通知。

## 本机制怎样执行

需求全部完成 → 权重选择奖励 → 原格替换并通知变换 → 按允许点击状态决定震动 → 发吞噬通知。

本页说明这一步的条件与结果；下一层给出对应变量、比较、完整配表与数值推演。

## 演示案例

本例设定本机制所需条件，演示它实际触发后的结果。

### 场景1：最后一件触发奖励变换

**本例情境：** 目标需要两件201，已吞一件；玩家拖入最后一件，变换奖励配置有效。

**判断与目的：** 补齐需求后独立按权重选奖励，目标原位变换。

**玩家看到的结果：** 拖入201和吞噬目标都消失，目标格出现203，能量仍10；这次不走普通气泡或金币奖励。
