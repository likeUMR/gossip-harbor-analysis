# 普通交付：算奖励并先发即时奖励

普通链先按需求算价格与难度，再按活动资格收集奖励，分出延迟奖励并保存快照。随后发即时奖励、亲密度礼物与Buff奖励，处理订单微笑分数。此时材料尚未扣除，不能把发奖与扣物理解成一个不可分割的事务。

## 本阶段的判断与处理顺序

1. **价格、难度与金币类型**：价格和难度都逐项累加，重复需求重复计入。基准订单可使用推荐价格；金币Buff在最终价格上翻倍。BakeOut可把最后的基础奖励改成代币，亲密度随机订单可能没有这份基础奖励。

2. **按顺序收集活动奖励**：活动资格在本次读取时判断，按原调用顺序追加。限时订单提供的相册信息会影响普通相册奖励；宝箱顾客追加的是延迟领取标记。奖励列表顺序不等于分类处理器之间的执行顺序。

3. **即时与延迟奖励分离、冻结快照**：根据宝箱顾客前缀拆分奖励，普通部分马上发，标记部分稍后发。两份都复制，确保完成消息展示的是提交时的结果。

4. **奖励落账与棋子进入缓存**：奖励逻辑先转换动态奖励，再按类别交给处理器。货币更新资源，普通棋子奖励进入缓存；这不是统一把所有奖励直接放到棋盘。逻辑落账与飞行动画分别执行。

5. **亲密度礼物与Buff奖励**：即时奖励之后才处理礼物，再处理Buff。礼物须亲密度开放；Buff由订单提供的接口决定。它们与最后的金币翻倍是不同调用，不能简单把全部奖励再乘2。

6. **订单微笑分数与首轮提示**：材料扣除前处理订单微笑进度，更新该槽已完成次数并保存。首个普通微笑的提示要等普通链末尾才派发。它不是普通金币奖励，也不等于每张订单固定加1。

## 演示案例

下面分别改变前提，让各条分支实际发生；互斥结果属于不同场景。

### 场景1：金币Buff翻倍

**本例情境：** 订单物为203两件和204一件，分别改变金币Buff、基准单或奖励类型条件。

**判断与目的：** 逐件算价和难度，再把最终金币价翻倍。

**玩家看到的结果：** 本单发16金币，余额100变116，难度累计本次贡献9；不是三件物品各只算一次。

### 场景2：基准单采用推荐价

**本例情境：** 订单物为203两件和204一件，分别改变金币Buff、基准单或奖励类型条件。

**判断与目的：** 基准单优先采用推荐价格，普通难度值保持各物配置。

**玩家看到的结果：** 本单发12金币，余额变112，难度贡献仍9。

### 场景3：烘焙代币替代金币

**本例情境：** 订单物为203两件和204一件，分别改变金币Buff、基准单或奖励类型条件。

**判断与目的：** 基础奖励类型改为烘焙代币，数量仍按订单价格结算。

**玩家看到的结果：** 获得8个烘焙代币，代币变13；这份基础奖励不会同时再发8金币。

### 场景4：亲密度随机单不发基础金币

**本例情境：** 订单物为203两件和204一件，分别改变金币Buff、基准单或奖励类型条件。

**判断与目的：** 该类订单关闭基础金币奖励，仍可按独立礼物流程发奖励。

**玩家看到的结果：** 本单不发基础金币；礼物提供5能量，能量变15，避免误认为没有金币就没有任何收益。

### 场景5：活动奖励与相册修正

**本例情境：** 本场景专门满足所述活动的领奖条件，并提供它本次返回的奖励。

**判断与目的：** 按调用顺序收活动奖励，相册Buff加倍该包，末尾追加金币。

**玩家看到的结果：** 得到3个装饰代币、2个竞速代币、4个街道代币和8金币；相册获两包，体现相册加倍而非全部奖励加倍。

### 场景6：限时标记避免重复相册

**本例情境：** 本场景专门满足所述活动的领奖条件，并提供它本次返回的奖励。

**判断与目的：** 限时订单发现相册标记后跳过普通相册追加，避免重复。

**玩家看到的结果：** 本函数只追加8金币，避免再加一份普通相册包；限时奖励的实际发放由限时订单自己的流程负责。

### 场景7：向上活动实际追加奖励

**本例情境：** 本场景专门满足所述活动的领奖条件，并提供它本次返回的奖励。

**判断与目的：** 执行到向上活动的收集位置，该活动有奖便追加，末尾继续加入基础金币。

**玩家看到的结果：** 收到3份向上活动奖励，原来5份变8份；另得8金币，金币余额108。

### 场景14：即时奖励和宝箱标记分离

**本例情境：** 本次奖励同时包含8金币和一个合法宝箱顾客标记。

**判断与目的：** 前缀识别把标记留给稍后处理，分别复制两份快照。

**玩家看到的结果：** 先领取8金币；宝箱标记暂留在延迟结算中，不被当成金币或直接一件棋子。

### 场景15：货币入账与棋子入缓存

**本例情境：** 本次奖励包含8金币和两件204，缓存原为空。

**判断与目的：** 按类别处理，金币变资源，棋子按数量展开入缓存。

**玩家看到的结果：** 金币余额108，缓存增加两件204；棋盘不会凭这一步直接多两件204。

### 场景16：礼物和Buff分别发放

**本例情境：** 亲密度已开放，本单礼物给3金币，另有Buff给5能量。

**判断与目的：** 先单独发礼物，再单独发Buff，不重复发基础金币。

**玩家看到的结果：** 总共收到11金币和5能量，余额111、能量15；其中礼物3金币与Buff5能量是额外两次结算。

### 场景17：首个普通微笑订单

**本例情境：** 普通槽1进入微笑活动首轮，本次可加一份微笑进度。

**判断与目的：** 读取本槽微笑奖励，更新活动分数和完成次数，首轮提示留到末尾。

**玩家看到的结果：** 微笑进度变1分，本槽记一次完成；正常交付结算完才出现首个微笑相关提示。
