# 活动奖励收集：具体算法与配置

GetRewards若Finished返回缓存DeepCopy，若Special返回空表。正常追加顺序：主装饰代币(Started对象且CanAddScore，数量>0)→FloatRace(CanAddScore且非nil)→TimedOrder检查GetTimedOrderRewards中是否含相册缓存奖励并设skipAlbumReward（这里没有把整份TimedRewards追加！）→未跳过时Album(IsActivityOpen)按diff/slot或orderType+innerType取包并复制，CanSupportAlbumBuff再×2；相册Buff还要求buff激活、非Timed/非Special且预览false调用结果非空→Avenue正分→Upward非nil→Road正分→HitBricks资格调用为真再调用一次取奖→Ring真→Combo真→ActivityModuleManager各模块GetRewardsByOrder返回非空数组追加→ChestCustomer槽追加RewardKey..innerType.."_"..slot,count1→基础金币/BakeOut。

ActivityModuleManager以pairs遍历注册模块，不保证跨模块固定顺序；各GetAddScoreByOrder内部资格/公式与远端档位属于具体活动，不能把“活动开启”当成必定有奖。

## 演示案例

下面分别改变前提，让各条分支实际发生；互斥结果属于不同场景。

### 场景1：活动奖励与相册修正

**完整输入（演示设定）：** 普通槽1订单需求按序203、203、204；棋盘(1,1)/(2,1)各裸203，仓库索引1裸204，缓存空；等级10，Gold100、Energy10、TotalDiff100。203价格2/难度2，204价格4/难度5。假设主装饰Started且可计分返回代币3；FloatRace返回2代币；TimedRewards不含相册包；Album开放返回相册包1且AlbumBuff可支持并激活；Avenue返回4，其它活动无奖励，非宝箱槽。

**按执行顺序代入：** 追加DecorToken3→FloatRaceToken2→AlbumPack1×2=2→AvenueToken4→Gold8；假设初余额Decor5/Race7/Avenue6，逻辑落账后分别8/9/10；Gold108，相册处理器收到2包。

**玩家看到的结果：** 得到3个装饰代币、2个竞速代币、4个街道代币和8金币；相册获两包，体现相册加倍而非全部奖励加倍。

### 场景2：限时标记避免重复相册

**完整输入（演示设定）：** 限时订单内部类型TimedOrder，价格8、难度9；假设GetTimedOrderRewards存在且含相册缓存标记，Album开放，其它直接活动奖励为空。

**按执行顺序代入：** skipAlbumReward=true；此GetRewards未把TimedRewards整体追加；输出此函数rewards=[Gold8]。

**玩家看到的结果：** 本函数只追加8金币，避免再加一份普通相册包；限时奖励的实际发放由限时订单自己的流程负责。

### 场景3：向上活动实际追加奖励

**完整输入（演示设定）：** 普通槽1订单需求按序203、203、204；棋盘(1,1)/(2,1)各裸203，仓库索引1裸204，缓存空；等级10，Gold100、Energy10、TotalDiff100。203价格2/难度2，204价格4/难度5。本例独立开启向上活动并满足其活动资格；假设对应接口给出合法活动奖励3份，其类型由活动实际返回，旧计数5；其它活动奖励为空。

**按执行顺序代入：** Upward有效返回3；奖励列表=[该活动奖励3,Gold8]；对应处理器计数5+3=8，Gold100+8=108。
