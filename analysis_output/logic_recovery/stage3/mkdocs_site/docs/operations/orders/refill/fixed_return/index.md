# 固定与回归订单

Baseline 是补位阶段的独立回归分支：Slot15 可用、补位扫描发生、距上次记录至少 60 秒且棋盘存在候选时才尝试生成。首次计时为 `-1` 时只写服务器时间，本轮不生成；它不是每 60 秒后台自动创建。历史中的 14 个指定棋子和库存清理单因此只能在该分支的候选与保存步骤使用。

固定单按进度的下一Id和槽/等级门槛创建，不随机需求。回归免费单在指定槽与回归时间内取现有较高等级物；计时资格与选物是两个步骤，构造失败也可能已经改计时。

## 内部处理顺序与目的

1. 固定订单先看下一进度、允许槽位和等级，需求直接读表。

2. 固定未成功才可能检查回归免费资格和八小时计时。

3. 回归单从现有较高等级物中均匀选需求，此时不扣物。

## 演示案例

下面分别改变前提，让各条分支实际发生；互斥结果属于不同场景。

### 场景1：预设需求创建固定单

**本例情境：** 分别演示固定进度达标，以及回归奖励期等待八小时后的免费单。

**判断与目的：** 固定单看下一进度和资格，需求照表保留。

**玩家看到的结果：** 新顾客只要一件203，固定进度推进到1；没有随机挑需求。

### 场景2：回归八小时后免费单

**本例情境：** 分别演示固定进度达标，以及回归奖励期等待八小时后的免费单。

**判断与目的：** 计时达到八小时后，从允许等级的最高现存物中等权选需求。

**玩家看到的结果：** 出现只要一件507的回归免费订单；507仍在棋盘，本步只是创建需求，尚未扣物。
