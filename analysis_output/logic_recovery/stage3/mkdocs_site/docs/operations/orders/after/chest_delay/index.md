# 宝箱顾客奖励

先派宝箱顾客完成通知，然后发快照中各组延迟奖励。通知本身与奖励标记落账不同；两者都发生在槽位补位之前。

## 内部处理顺序与目的

1. 先派宝箱完成通知，再依次处理延迟奖励组。

2. 宝箱标记换成难度预算，抽奖励方案，再展开成具体棋子。

3. 能落盘的先生成，其余进缓存，保存展开结果供视图展示。

---

## 演示案例

下面分别改变前提，让各条分支实际发生；互斥结果属于不同场景。

### 场景1：预算允许最后一件超支

**本例情境：** 宝箱活动有效，旧订单仍可取到；预算五份、每件203成本三份，棋盘一个空格。

**判断与目的：** 通知宝箱完成，再把标记换成预算，重复抽物直到预算耗尽，不能把标记当一件奖励。

**玩家看到的结果：** 共获得两件203，一件在棋盘、一件在缓存；预算虽是5，最后一件允许跨过预算边界。

### 场景2：缺口整单容差补齐

**本例情境：** 宝箱活动有效，旧订单仍可取到；预算五份、每件203成本三份，棋盘一个空格。

**判断与目的：** 预算接近整张订单所缺难度时，允许小幅超预算，直接给齐缺口。

**玩家看到的结果：** 棋盘多一件203和一件204，把这张订单的缺口全部补齐；预算允许超出两份。

### 场景3：高难度缺口用旧降阶算法

**本例情境：** 宝箱活动有效，旧订单仍可取到；预算五份、每件203成本三份，棋盘一个空格。

**判断与目的：** 整件目标远超预算，沿同链降到较便宜等级，按预算向上取整发帮助物。

**玩家看到的结果：** 棋盘获得两件206，帮助继续合成209；没有直接发出209，末件仍允许超预算。

### 场景4：库存优化停止定向后用余款补奖

**本例情境：** 宝箱活动有效，旧订单仍可取到；预算五份、每件203成本三份，棋盘一个空格。

**判断与目的：** 考虑现有低阶合成库存，只补尚缺的等价份额，再把余款转为普通五级奖励。

**玩家看到的结果：** 棋盘额外获得一件206和两件205；定向补缺没有继续重复发206，剩余预算仍作为普通奖励用完。
