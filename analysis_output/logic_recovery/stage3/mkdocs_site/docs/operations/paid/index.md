# 付费项目

本批以真实付费对象为第二层目录。第三层解释资格、候选、价格、次数和生命周期；第四层记录字段、执行顺序、边界、来源和假设案例。

## 总体执行骨架

1. 装载 IAP、商店、每日特惠、闪购和礼包组配置。
2. 按入口建立常驻或动态候选。
3. 检查等级、触发物品、订单/能量状态、活动开关、周期、购买记录和冷却。
4. 应用同组优先级、互斥和弹窗限制。
5. 用 purchaseId 关联 goods、展示价格和本地化 IAP 商品。
6. 成功购买/领取后发奖，写购买、阶段、过期和恢复状态。

本批当前是静态规格推进，服务端 payload、账号投放分组和原版回放分别标记为 runtime-pending 或 unavailable。

## 历史价格与经济结论的实际入口

历史棋子分析中的商店刷新费用、次数递增、Series 价格曲线和三种钻石路径，均在商店候选、礼包价格和价值换算阶段使用。价格拟合只能说明参考模型；购买页面仍按 `costCount`、`costIncreasement`、`ShopCount`、刷新入口和购买回调说明实际状态变化。订单金币固定性与金币/体力比较进入订单奖励页面，不能反向当作付费配置。

历史分析还涉及远端模式 1/2、玩家 tier、闪购需求修正和服务器变体；这些现在统一放在[用户差异与配置分层](segmentation/index.md)，按文件替换、活动 payload、通用开关三种控制方式解释。没有真实账号后缀或服务端值时，页面保留 runtime-pending。
