# 后续通知怎样影响下一件物品

本次生成的代码和来源类型会进入落子通知。各监听者根据自己的条件响应；不能只凭“Lucky命中”概括为活动进度必加1。

## 处理位置与含义

1. 落子之前，记录此次能量指数历史，供后续Lucky调整升级档。
2. 主棋子落子通知携带Source、New、来源类型和能量指数。GeneratorBoost普通双倍资格在候选阶段先确定，收到通知后才复制实际产物。
3. Lucky类通知在指定Buff开启且有空位时也能复制实际产物；连续Lucky类型不在此监听的条件内。
4. 追加类型与主类型不同，避免同一监听再次无限复制；其它进度、提示、声音按各自监听条件处理。

本次“生成物品”可能通过通知引出第二次SpreadItem，但它不重新抽本次普通或Lucky物品池。[底层说明](detail.md)列出资格池、缓存、位置检查和复制参数。

## 同一通知还可能推进什么

监听不是所有账号必经的一串步骤。各自先判断活动和事件资格，再进入自己的状态分支：卡片先检查库存与完成状态，再累计能量、判断阈值，最后决定续用旧链或抽新链；密室先按锁定/解锁状态分流，分别推进钥匙或工具奖励。一项活动不满足条件，不阻止其它监听响应。

卡片停止条件、换链和数值对照见[卡片具体流程](detail.md#card-flow)；密室解锁、跨轮奖励和到期重置见[密室具体流程](detail.md#room-flow)。这些分支也会发出后续通知，因此只看到主物品落下还不能视为点击链结束。

## 贯穿案例：点击食品袋 105

**目的**：制作食物，观察同一次点击怎样从前置检查进入当前页面所解释的分支。

**本页发生什么**：本例假设母体支持 ExtraLuckyProduce 且主产物命中 Lucky。落子通知触发复制监听，玩家看到同一件物品在另一个空位再出现；复制不重新抽 Lucky 池。

### 代入本页的值

对照主Lucky代码204、有一个追加空位、ExtraLuckyProduce Buff有效时：再落一件204，追加类型GeneratorBoostExtraLucky且costEnergy=false。是否另增某项任务进度须由对应任务监听决定，不能统一写+1。
