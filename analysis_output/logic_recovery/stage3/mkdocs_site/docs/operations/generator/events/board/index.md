# 棋盘事件

`BoardModel:SpreadItem` 写入新棋子和来源信息；成功后发送 `VibrationLight`，母体状态通过 `ItemSpreadEventType.StateChanged` 通知视图。

**证据状态**：主判断和字段为 `source-confirmed`；服务器开关、动态活动对象、实际回放时序为 `runtime-pending`。

具体写入与派发顺序见[棋盘事件底层说明](detail.md)。
---

## 贯穿案例：点击食品袋 105

**目的**：制作食物，观察同一次点击怎样从前置检查进入当前页面所解释的分支。

**本页发生什么**：本例物品成功写入空位 P，玩家看到棋盘新增 1 个物品；若棋盘已满，只看到棋盘已满提示，不会写入物品。

### 代入本页的值

假设合法落点 P 存在且产出物品 201。写入棋盘后发送 `BoardItemAdded(item=201,pos=P)`，再发送 `BoardChanged`；若没有空位，则在写入前返回 `false`，只发送 `BoardFull`。

共同演示输入：等级 10、活动 Started、余额 10、次数 80、储备 240、有效空格 P。每个页面会为本页机制单独假设触发条件，并给出完整结果；其它机制只有在需要隔离当前分支时才单独说明。所有新增配置和数值均为演示假设。

本页案例只把当前机制设为触发条件；其它机制若被隔离，会在该段中明确说明假设。
